# Wasp Starters

This directory contains starter templates for creating new Wasp projects.

## How Wasp Starters Work

When you create a new project using `wasp new`, Wasp creates the project in 3 steps:

1. **Copy skeleton files**: Wasp copies the [`skeleton`](./skeleton) files into the project directory
2. **Copy starter template files**: Wasp copies the chosen starter template files (e.g., `basic`) into the project directory
3. **Replace placeholders**: Wasp replaces template placeholders in the project files (e.g., app name)

Due to this behavior, all files shared by all starters are placed in the [`skeleton`](./skeleton) directory.

## Development Workflow

The recommended approach for developing starter templates:

1. **Create a test project**: Create a new project with the starter you want to modify
2. **Implement changes**: Make your required changes in the Wasp project
3. **Copy changes back**: Once satisfied with the implementation, copy the files from your project back to the starter templates
4. **Regenerate the lockfile**: If you changed a starter's `package.json`, run `./run update:starter-lockfiles`
5. **Test the starter**: Create a new project with `wasp-cli` to verify it matches your previously created project

## `package-lock.json`

Each starter ships a `package-lock.json` so that the initial `npm install` in a
new project finds a pre-resolved dependency tree: the install is faster, and
every new project starts from the same known-good dependency versions.

The lockfiles are what `wasp new` + `wasp install` would produce in a fresh
project, except that the app name is the `__waspAppName__` placeholder (replaced
by `wasp new`, like in `package.json`). They are generated by
`waspc/tools/starters/generate-lockfiles.ts`:

- `./run update:starter-lockfiles` regenerates them, keeping already-pinned
  versions and picking up in-repo changes (a starter's `package.json`, the
  `@wasp.sh/spec` package, ...).
- `./run update:starter-lockfiles --refresh` re-pins all dependencies to the
  latest versions their ranges allow.
- `./run check:starter-lockfiles` verifies they are up to date. CI runs this on
  every PR, and `./run version-bump` regenerates them automatically.
